复杂数据库任务通常需要先查表和字段，再试跑查询、观察报错或空结果，最后修改并提交 SQL。只训练“问题到正确 SQL”的映射，会漏掉中间决策。北京时间 10 月 9 日公开的 [HarnessSQL](https://arxiv.org/abs/2610.12274) 把运行时纳入数据生成、监督微调和强化学习，让小模型学习整个数据库交互过程。

框架先从真实数据库提取结构、样例值与连接路径，以可执行 SQL 为蓝图生成问题及隐藏的结果校验器。候选任务需要通过语法、空结果和退化连接等筛选，还用查询变异检查任务是否能区分语义错误。隐藏答案用于验收，模型看到的是任务与工具反馈；这使数据生产同时具备可执行环境和明确的成功条件。[论文方法](https://arxiv.org/html/2610.12274v1)详细描述了这些筛选步骤。

交互接口收敛为四个动作：列出表、查看结构、执行查询和提交答案。工具语义、结果截断、错误格式与终止条件都会影响模型下一步决策，因此训练和部署使用相同协议。评测任务在独立子进程中运行，数据库只读，执行有时间限制；未调用 `sql_submit` 就结束的任务计为失败。正确查询还必须按协议提交，不能只从对话末尾猜测答案。[官方代码](https://github.com/YangHaolin0526/HarnessSQL)提供数据库转换、任务合成、轨迹采集、SFT 和 RL 入口。

教师模型也在这个接口里解决任务，只有通过执行校验的轨迹进入训练。SFT 将一整段交互作为一个样本，对各轮助手输出计算损失，工具观察作为条件保留但不参与损失。随后 RL 在同一环境中，根据最终执行结果给予二元奖励。论文使用 2,512 条 SFT 轨迹，RL 训练池包含 2,700 个任务；训练信号不仅描述怎么写查询，也包含何时检查、如何恢复和什么时候结束。[训练配置与消融](https://arxiv.org/html/2610.12274v1)支持这一流程。

作者在 Spider 2.0-SQLite 的 135 个任务上报告，Qwen3-8B 的执行准确率从 15.5% 经 SFT 提高到 30.4%，继续 RL 后达到 45.2%；14B 对应为 22.2%、37.8% 和 54.8%。8B 直接做 RL 为 20.0%，说明在这组实验中，交互轨迹提供了有效冷启动。跨域结果也有差异：14B 在 BIRD-Interact Mini 为 11.3%，在 LiveSQLBench Base-Lite SQLite 为 28.5%。这些是不同协议下的作者实验结果，实际选型应保留各套任务的口径。[结果表](https://arxiv.org/html/2610.12274v1)同时列出基线与训练阶段。

同类路线的区别在于监督单位。[OmniSQL](https://github.com/RUCKBReasoning/OmniSQL)通过 SynSQL-2.5M 扩大数据库、问题、SQL 和思维链样本的覆盖，推理模板接收结构与问题后生成查询。它适合增强静态查询生成能力；HarnessSQL 则把工具反馈后的连续动作作为训练对象。两者都使用合成与验证，数据规模和运行时交互是不同设计维度。

[CoTrace](https://arxiv.org/html/2610.10426v1)同样强调轨迹与运行时匹配，但面向终端 Agent，将失败证据用于调整 harness，将验证成功的匹配轨迹用于更新模型，并分别检查两条优化路径的收益。HarnessSQL 的本次方案固定精简 SQL 协议，再进行 SFT 与 RL。前者更关注运行时与模型的持续共同演进，后者提供数据库领域的具体训练闭环；选择取决于工具接口是否稳定，以及错误主要来自运行时还是模型行为。

对已有 SQL Agent，第一步可以先统一生产与采集时的工具契约，记录数据库版本、错误反馈、截断和提交动作，再积累可回放的成功轨迹。第二步把多指标、多窗口查询拆成可校验任务，保留试执行和修正过程，用结果校验筛掉语法合法但业务语义错误的样本。接口稳定、轨迹足够后，再评估 SFT 与执行奖励 RL 的收益，而不是只扩大最终 SQL 答案库。

长轨迹还涉及上下文预算。作者将训练和 RL 的上下文上限同时从 8K 增至 32K 时，8B 在 Spider 2.0-SQLite 的准确率从 27.4% 提高到 45.2%。这提示数据导出时应检查早期结构和执行证据是否被裁掉，并把截断策略与上线配置一起记录。[上下文消融](https://arxiv.org/html/2610.12274v1)给出了各任务集的变化。

跨数据库部署还需要对应的执行环境。论文主要覆盖 SQLite；Snowflake、BigQuery 或 PostgreSQL 的方言、元数据命令与客户端行为都进入交互过程，不能只替换连接地址。迁移时应重新生成该环境中的轨迹，并保留独立任务做回归测试。这也把后续工作从单纯优化提示词，推进到可验证的数据、工具协议与模型训练协同设计。[论文限制及复现代码](https://github.com/YangHaolin0526/HarnessSQL)给出了当前范围与运行依赖。
